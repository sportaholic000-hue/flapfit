# Required Apple age check in the production lobby

The previous implementation required a confirmed coarse jurisdiction before requesting any Apple age range. That made Apple's required system check wait for a separate region decision. The production lobby now reacts to the existing root duty lookup. After existing onboarding, when Apple positively reports that its check is required, the lobby invokes the native age-range API without a custom age/residence question. Apple controls the system-sheet wording and whether previously shared information can be returned without a sheet.

This implements only the mandatory system-check branch. A not-required, unsupported, pending or failed duty lookup does not show this branch's sheet and is not an adult classification. A successful age response does not authorize advertising, RevenueCat, competition, or every use of personal data. The mandatory-only result leaves all policy assessments unresolved; no country, raw age bounds or Apple parental/account fields are persisted or exposed to SDKs. Existing regional requests still need an established context before they resolve purpose decisions.

The native presentation barrier also covers this Apple sheet. An unsettled result ad or Google rights request finishes first. Leaving the lobby or starting a game before dispatch prevents a late sheet; a sheet already dispatched must complete before camera/game entry. Concurrent requests share native ownership. The ordinary lobby return after refusal does not automatically repeat the same attempt; a new launch or explicit account/duty invalidation allows a fresh check. Joining an existing regional Apple request preserves it rather than invalidating it.
