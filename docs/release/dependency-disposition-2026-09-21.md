# Flap Fit per-advisory disposition — September 21, 2026

This assessment supersedes generic deferral wording in the earlier dependency audit. The retained locked-graph scan has **28 security rows, 18 unique advisories, 22 high rows, 6 moderate rows and no critical rows**, plus six deprecation notices. No dependency upgrade was made; the scan is not clean. Advisory metadata and patched versions were retrieved from GitHub's publisher-linked advisory records during this continuation.

## Verified input boundaries

- **XML tooling:** installed xmldom 0.9.10 is reached through plist 3.1.1, and 0.8.13 through @expo/plist 0.8.1. Their parse implementations call DOMParser for plist XML; both build implementations use xmlbuilder rather than xmldom serialization. These consumers are native-project/configuration tooling, not application routes for camera, recordings, score names, challenge data or API JSON. Do not process unreviewed external XML or build untrusted branches with credentials on the basis of this disposition.
- **YAML tooling:** js-yaml 3.15.1 is used by @istanbuljs/load-nyc-config 1.1.0, and 4.3.1 by @eslint/eslintrc 3.3.6. Actual callers load local test/lint configuration. The app/backend has no user YAML ingestion path.
- **CSS tooling:** PostCSS 8.5.12 is the direct mobile dev dependency. postcss.config.js uses tailwindcss/autoprefixer. Application-source searches found no affected PostCSS runtime parser or externally supplied CSS input; the bundled MediaPipe JavaScript source-map comment is not CSS input. A malicious contributor can still poison a build input; this report does not certify running unreviewed source safely.
- **UUID tooling:** xcode/lib/pbxProject.js generates IDs with uuid.v4(); @expo/ngrok/index.js calls uuid.v4() for a tunnel name. Neither passes buffers or calls v3/v5/v6. Package.json dependency classification alone was not used to infer runtime reachability.

## Individual decisions

Every row below is a local build/development/test dependency path, not a demonstrated installed-app or Edge Function attack path. Version ranges remain vulnerable; the decision is based on the actual operation and input boundary, not severity alone or failure to reproduce an exploit. Patched patch-line releases are available for XML/YAML/PostCSS. They are reasonable later maintenance candidates, but the assessed app has no exposed affected input route requiring an emergency pre-build override. If an external-input route is introduced, upgrade the affected package before enabling it and validate the actual consumer. No claim is made that all patch updates are incompatible with Expo.

## Runtime repair already preserved

The separately identified decode-uri-component 0.2.2 malformed-URL denial of service was reachable through Expo Router. Its narrow official-scanner backport was already applied and tested; the current lock/patch/consumer source is unchanged. Existing legacy/upstream/query-string/stress evidence remains applicable. It is not included in the current 28 advisory rows and must not be described as still unmitigated merely because an older September 19 paragraph says so.

Deprecated abab, domexception, glob, inflight, whatwg-encoding and ESLint-related notices are retained as maintenance items, not invented runtime exploits. No broad SDK/lock refresh or forced major-version resolution was applied. Current TypeScript, lint, configuration and regression checks passed; they are not vulnerability proofs. These tooling advisories are not, by themselves, demonstrated App Store rejection blockers.
